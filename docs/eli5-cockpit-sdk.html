조종석과 Claude Code 한 몸

cockpit 은 Claude Code 를 흉내 낸 물건이 아닙니다. 터미널에서 쓰던 그 Claude Code 를 브라우저 창에 끼워 넣은 것입니다. 같은 프로그램, 같은 설정 파일, 같은 대화 기록. 바뀐 것은 글자가 오가는 창구뿐입니다.

등장인물 넷

누가 무엇을 맡나

사람 김피엘 브라우저에서 방에 글을 씁니다. 승인 카드에 답하는 것도 이 사람뿐입니다.
서버 cockpit 웹 화면을 띄우고, 글을 받아 봇에게 건네고, 봇이 한 일을 기록합니다.
일꾼 Claude Code CLI 실제로 생각하고 도구를 쓰는 쪽. 터미널에서 claude 라고 칠 때 뜨는 그 프로그램입니다.
현장 봇 폴더 지침·훅·스킬이 놓인 작업 자리. CLI 는 여기에 서서 일을 시작합니다.
그림 1 · 큰 그림

글 하나가 지나가는 길

브라우저에서 시작해 봇 폴더까지 한 줄로 이어집니다. 가운데에 있는 query() 가 Claude Code 를 자식 프로세스로 띄우는 자리입니다.

의존성 둘

프레임워크는 없습니다

cockpit 은 순수 Node 앱입니다. 웹 프레임워크를 쓰지 않고 node:http 하나에 길을 나눴습니다. 화면도 빌드 도구와 CDN 없이 정적 파일 그대로입니다. 설계 결정 ADR-010 에 그렇게 적혀 있습니다.

의존성하는 일
@anthropic-ai/claude-agent-sdk 0.3.270Claude Code CLI 를 자식 프로세스로 띄우고 JSON 메시지로 주고받습니다.
zod도구 입력값의 모양을 검사합니다.

옛 방식(minidiscord)에서는 채팅 서버가 channels 플러그인으로, 사람이 터미널에서 켜 둔 Claude Code 세션을 두드렸습니다. 회사가 channels 를 막으면서 그 길이 끊겼습니다. cockpit 은 웹 서버 자신이 봇 세션을 띄우고 붙들기로 방향을 바꾼 결과입니다.

그림 2 · 왕복 한 번

글을 올리면 벌어지는 일

서버는 방에 올라온 글을 봉투에 쌉니다. 봉투 안에는 chat_id, message_id, 보낸 이, 방 이름, 첨부 경로가 들어갑니다. 봇이 답할 때 어디로 보내야 할지 알 수 있게 하는 표식입니다.

비밀 하나

세션 창은 서버가 아니라 프로세스가 들고 있습니다

query() 의 prompt 자리에 문자열 대신 끝나지 않는 입력 큐를 넘깁니다. 큐가 끝나지 않는 한 SDK 는 CLI 프로세스를 죽이지 않습니다. 사람이 글을 올리면 서버는 큐에 한 줄 밀어 넣을 뿐이고, 같은 프로세스에서 다음 턴이 돕니다.

그래서 대화 문맥은 cockpit 의 데이터베이스가 아니라, 살아 있는 CLI 프로세스 안에 있습니다. 터미널 창을 켜 둔 채 계속 말을 거는 것과 똑같습니다.

밀린 글이 여럿이면 id 순서로 묶어 메시지 하나로 만듭니다. 한 번에 스무 개까지입니다.

껐다 켜도 이어짐

대화는 파일에 남아 있습니다

CLI 는 대화 기록을 ~/.claude/projects/<봇 폴더 경로>/<session_id>.jsonl 에 남깁니다. cockpit 은 첫 init 사건에서 받은 세션 번호를 cockpit.db 에 적어 둡니다. 끄기는 프로세스를 닫는 것이고, 다시 켜기는 resume 에 그 번호를 넣어 부르는 것입니다.

상황결과

기록이 없을 때resume 이 실패하면 새 세션으로 켜고 그 사실을 사건으로 남깁니다.
값과 문맥 사용률프로세스 단위라 재기동 뒤 0 부터 다시 셉니다. cockpit 이 정지 시점 값을 바닥으로 두고 더합니다.

터미널에서 켠 것과 무엇이 다른가

두 길은 출발지만 다르고 도착지가 같습니다. 읽는 파일이 같기 때문입니다.

SDK 는 실제로 이렇게 불립니다

위의 그림을 코드로 옮기면 여섯 장면입니다. 비유 하나로 먼저 잡고 들어가겠습니다. SDK 는 전화기, Claude Code 는 전화 건너편의 일꾼입니다. cockpit 은 전화를 한 번 걸어 끊지 않고 붙들고 있다가, 사람이 글을 쓰면 수화기에 대고 말을 전하고, 일꾼이 하는 말을 받아 적습니다.

아래 코드는 실제 파일에서 가져오되, 흐름과 상관없는 줄은 … 로 줄였습니다. 파일 이름 옆 숫자는 줄 번호(cockpit d41b0da 시점)입니다. 장면 순서는 세션 하나가 켜져서 답을 보내기까지의 실제 순서입니다.

1

전화기는 한 대만 둡니다

SDK 를 불러오는 파일이 딱 하나입니다. 나머지 코드는 이 파일이 내준 함수 두 개만 받아 씁니다. 그래서 시험할 때는 진짜 전화기 대신 장난감 전화기를 끼울 수 있습니다.

src/session/sdk-query.js4 · 20–22

쓰는 SDK 기능은 셋입니다. 세션을 띄우는 query, 봇에게 줄 도구 상자를 만드는 createSdkMcpServer, 도구 하나를 정의하는 tool. 시험은 test/fakes/fake-query.js 의 모의 queryFn 을 대신 넣습니다.

2

전화 걸기 전에 쪽지를 챙깁니다

"어느 폴더에서 일할지, 무슨 설정을 읽을지, 누구에게 허락을 받을지" 를 옵션 한 묶음에 적습니다. 이 묶음을 만드는 곳도 한 자리뿐입니다.

src/session/options.js11–31
export function buildQueryOptions({ botDir, mcpServer, canUseTool, env, resume, … }) {
  const options = {
    cwd: botDir,                              // 봇 폴더에 서서 시작 → CLAUDE.md · 훅 · 스킬을 CLI 가 스스로 읽는다
    settingSources: ['project', 'local'],   // 'user' 가 없다 → ~/.claude 는 안 읽는다
    strictMcpConfig: true,
    mcpServers: { cockpit: mcpServer },        // 장면 6 의 도구 상자
    permissionMode: 'default',
    allowedTools: ['mcp__cockpit__reply', 'mcp__cockpit__fetch_history'],
    canUseTool,                                // 장면 5 의 승인 카드
    persistSession: true,
    env,                                       // 화이트리스트만. 서버 비밀이 봇에 안 샌다
    includePartialMessages: true,
    enableFileCheckpointing: true,
    systemPrompt: { type: 'preset', preset: 'claude_code', append: INSTRUCTIONS, snapshot: true },
  };
  if (resume) options.resume = resume;       // 껐다 켤 때 같은 session_id
  return options;
}

allowedTools 에는 cockpit 도구 둘만 넣습니다. 코드 주석에 따르면 이 목록에 든 도구는 승인 절차를 건너뛰기 때문에, 목록이 넓어지면 승인 카드가 조용히 사라집니다. 파일 읽기나 명령 실행 같은 나머지 도구는 봇 폴더의 settings.local.json 규칙과 승인 카드를 거칩니다.

3

전화를 걸고, 끊지 않습니다

prompt 자리에 글 한 줄이 아니라 비어 있는 우편함을 넘깁니다. SDK 는 우편함에 편지가 올 때까지 기다리고, 우편함이 닫히기 전에는 전화를 끊지 않습니다.

4

건너편 말을 한 줄씩 받아 적습니다

query() 가 돌려준 q 는 끝없이 흘러나오는 말줄기입니다. for await 로 한 줄씩 받아, 종류를 보고 화면에 띄울지 기록할지 정합니다.

src/session/manager.js237–372 줄임
async #pump(s, q, resumeId) {
  const init = await q.initializationResult();   // 계정 · 명령 · 도우미 목록
  this.#setState(s, 'idle');
  for await (const m of q) this.#onMessage(s, m);
}

#onMessage(s, m) {
  if (m.session_id) this.cockpitDb.setSessionId(s.project, m.session_id);  // 다시 켤 때 쓸 번호
  switch (m.type) {
    case 'stream_event': // 글자 조각 → 화면에만 흘린다. 저장 안 함
    case 'assistant':    // 봇이 tool_use 를 냈다 → "도구 씀" 사건
    case 'user':         // tool_result 가 왔다 → 걸린 시간과 함께 사건
    case 'result':       // 턴 끝 → total_cost_usd 적고, idle 로, 밀린 글 있으면 다시 넣기
    case 'system':       // init · 압축 · 훅 · 백그라운드 도우미 진행
  }
}

5

"이거 해도 돼요?" 를 사람에게 돌립니다

일꾼이 허용 목록 밖 도구를 쓰려 하면 SDK 가 canUseTool 을 부르고 답이 올 때까지 멈춰 섭니다. cockpit 은 곧바로 답하지 않고, 브라우저에 카드를 띄운 뒤 약속(Promise)만 돌려줍니다. admin 이 단추를 누르는 순간 약속이 풀리고 일꾼이 다시 움직입니다.

src/permissions/relay.js63–82 · 127–135 줄임
async handler({ project, toolName, input, options }) {
  const toolUseId = options.toolUseID;
  this.cockpitDb.insertPermission({ toolUseId, tool: toolName, input, … });
  this.emit('permission_request', …);          // 브라우저에 승인 카드

  return new Promise(resolve => {               // SDK 는 여기서 기다린다
    this.pending.set(toolUseId, { resolve, input, … });
    setTimer(() => this.#settle(toolUseId, { behavior: 'timeout' }), 10 * 60_000);
    options.signal?.addEventListener('abort', …);   // 멈춤을 누르면 거둬 감
  });
}

case 'allow':         return { behavior: 'allow', updatedInput: input };

"이번 세션 허용" 은 이름 그대로입니다. SDK 가 규칙을 파일에 영구 저장하자고 제안해도 destination 을 'session' 으로 바꿔 넣습니다. 그래서 봇 폴더에 허용 규칙이 몰래 쌓이지 않습니다.

일꾼 손에 도구 둘을 쥐여 줍니다

봇이 방에 답을 쓰는 방법은 하나, reply 도구를 부르는 것입니다. 이 도구는 외부 서버가 아니라 cockpit 프로세스 안에서 도는 함수라서, 부르면 곧장 채팅 DB 에 글이 들어갑니다.

// 봇이 mcp__cockpit__reply 를 부르면 도는 함수
async function reply(args) {
  const roomId = roomOf(args.chat_id);         // 봉투에 적혀 있던 방 번호
  const message = chatDb.insertBotMessage({ roomId, botId: bot.id, body: args.text, files: copyIn(args.files) });
  onBotMessage(message);                       // SSE 로 브라우저에 즉시
  return ok('sent');
}

봇 쪽에서 보이는 이름은 mcp__cockpit__reply 입니다. 이 이름과 매개변수 chat_id · text 가 prodev 의 "답 보내기 전 검사" 훅과 묶여 있어서, 바꾸면 훅이 헛돕니다.
